Feature gap review

SampleArk vs Sound Forge

Where today's build sits against a classic Sound Forge on ordinary sample-editing work — and what each missing piece would actually cost to build through the architecture that exists now.

Reviewed 20 Aug 2026, current working tree Updated undo/redo shipped same day Baseline Sound Forge 6–9 era Verified against app/src, not memory

The short version

  • 01
    The example you named is already at parity. Trim points drag on screen and normalise is wired. What's missing around them is precision: no zoom (the SAMPLE lane auto-fits by design), no zero-crossing snap, and a click anywhere in the lane grabs whichever handle is nearer rather than starting a selection.
  • 02
    Most of Sound Forge's Process menu is nearly free here. Reverse, invert, DC offset, RMS normalise, channel conversion and auto-trim are all parameter-shaped — one field in PrepParams, a few lines in renderInto, and they inherit into variations, recall and capture at no extra cost. That's the payoff of the non-destructive model.
  • 03
    Undo was the standout omission — and is now built. DONE 20 AUG It proved exactly as cheap as this predicted: every piece of editor state is a copyable value type, and the variations system already snapshotted that triple, so a 100-step history with gesture coalescing was a small job. No history window yet.
  • 04
    The real structural gap is the edit model. Cut, paste, insert, mix and duplicate all assume an editable buffer with a history. SampleArk assumes one immutable source, one contiguous region, and a stack of parameters. Nothing in that group is a small job, and they all become small together — or stay expensive individually.
  • 05
    Long files are the unstated boundary. Every change re-renders the whole region on a worker thread — ideal for one-shots and loops, unproven on the multi-minute recordings Sound Forge was built to chew through. Features that invite long-file work (recording, region extraction, batch) pull render and streaming behind them.

Reading the complexity column

Bands are effort relative to this codebase, not absolutes. The tail-control feature built this morning — model, render path, editor UI, ghost drawing, headless tests, docs — sat at the top of S, so use that as the yardstick.

XS

A field and a few lines inside the existing render path. No new UI concepts.

S

A parameter plus a control, or one self-contained scan/analysis. Touches two or three files.

M

A new subsystem or a genuine UI mode. Several files, no change to the core model.

L

Requires changing the model itself — an edit list, a destructive buffer, or a new engine.

Group C — Needs a new edit model

The genuine architectural gap. All of these assume you can rearrange the audio itself; the app assumes one immutable source and one contiguous region.

The option worth weighing

Group C has an unusually attractive third path. Rather than bolting on destructive editing with an undo stack, promote the single region to a list of segments that the renderer walks in order. Cut, duplicate, insert and reorder all become list operations, the model stays non-destructive, and undo stays a snapshot of a value type. The interesting part: a segment list is something the mutation engine could act on — shuffling, dropping or repeating slices at Massive and Unsafe depths is exactly the kind of variation this app exists to produce, and no Sound Forge ever did it. It is still an L, but it buys considerably more than parity.

What Sound Forge never had

Worth keeping in frame while reading a gap list: the mutation engine and its variation workspace, drawable transformer lanes modulating any effect parameter over the length of the sound, a live non-destructive rack that re-renders in the background as you turn knobs, the tail policy with its retained ring-out, and favourites batch-written with a manifest. None of that has an equivalent in any Sound Forge. The gaps below are about being a competent editor; that list is the reason to be a different tool.

If I were sequencing it

  1. Undo / redo. DONE — Built 20 Aug. Everything below is now safer to attempt.
  2. Reverse, invert, DC offset. XS each — One afternoon buys three named Sound Forge processes and they inherit into mutation for free.
  3. Zero-crossing snap. XS — Tiny, and it removes a class of clicks from loop work permanently.
  4. Zoom and scroll. M — The gate on every precision edit. Nothing above needs it; most things below do.
  5. Auto-trim, channel conversion, export formats. S each — Rounds out the prep stage and finishes the preferences surface several specs already assume.
  6. Then decide on segments. L — Group C, slicing and region extraction are one decision, not several. Worth taking deliberately rather than drifting into it.
